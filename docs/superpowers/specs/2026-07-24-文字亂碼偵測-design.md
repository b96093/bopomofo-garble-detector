# 文字亂碼偵測 — 設計文件

- 日期：2026-07-24
- 型態：Google Chrome 瀏覽器擴充套件（Manifest V3）
- 專案根目錄：`文字轉換器/`

## 一句話

台灣人打注音時常忘了切換輸入法，一整句打成英文亂碼。本擴充在使用者打字時**自動偵測**這種亂碼，於**游標旁就地浮出候選中文**，點一下即替換，讓使用者無須複製貼上、無須中斷。

## 問題與定位

- 忘了切輸入法 → 注音鍵位在英文模式下輸出成 Latin 字元。
  例：`JI394T AU04`（大千佈局）其實是要打「我愛吃麵」。
- 市面上已有「貼上→按鈕→轉換」的線上網頁工具，但**沒有**「自動偵測 + 就地提示」的擴充。本工具的獨特價值就在這個即時、免中斷的體驗。

## 使用者流程（目標體驗）

1. 使用者在網頁輸入框（如 FB 留言框）打字 `JI394T AU04`
2. 抬頭發現是亂碼
3. 此時游標旁**已自動浮出**候選提示窗
4. 顯示「我愛吃麵」（主）＋2 個備選（共 3 個）
5. 使用者點擊 / 按 Enter / 按數字鍵選字
6. 亂碼被替換成中文，使用者繼續打字
7. 若是誤判，按 Esc 忽略；**永不自動替換**

## 範圍決策（已與使用者確認）

| 項目 | 決定 |
|---|---|
| 輸出 | 直接到**漢字**（自動選字，方案 B） |
| 字典 | **詞庫**（以詞為單位選字），純前端內建、離線 |
| 鍵盤佈局 | 只支援**標準（大千）**佈局 |
| 偵測策略 | **保守**（三道關卡，寧靜勿擾） |
| 候選數 | 1 主 + 2 備，共 3 個 |
| 交付 | Chrome 擴充（商店上架 / 開發者模式載入） |
| 名稱 | 文字亂碼偵測 |

## 核心：三段式轉換管線（引擎）

```
亂碼字串  →①→  注音音節  →②→  漢字
JI394T AU04    ㄨㄛˇ ㄞˋ ㄔ ㄇㄧㄢˋ    我愛吃麵
```

**① 鍵位 → 注音（100% 確定性）**
以大千佈局對照表把每個 Latin 字元查回注音符號。關鍵洞察：注音每字須按**聲調鍵**送出
（`空格`=一聲、`6`=ˊ 二聲、`3`=ˇ 三聲、`4`=ˋ 四聲、`7`=˙ 輕聲），
故**聲調鍵天然是音節分隔點**，分段可靠、不需猜測。

**② 注音 → 漢字（詞庫比對）**
以「最長詞優先 / 最佳路徑」在詞庫中選字：`ㄞˋㄔ` 優先當「愛吃」而非「礙尺」。
無法成詞時退回該音節最高頻單字。

## 偵測器：三道關卡（保守）

判斷「一串 Latin 到底是注音亂碼、還是使用者故意打的英文」。三關全過才浮出提示：

1. **結構關**：能否乾淨切成合法注音音節？（最強；`the`→ㄔㄘㄍ 三聲母連續，不合法，直接淘汰大多數英文）
2. **詞庫關**：切出的音節能否拼出詞庫裡真正的詞？（提高把握）
3. **英文關**：反查一份常見英文單字表，若本身就是常見英文字則不跳。（保險）

灰色地帶（如極短字串 `au4`）以最小長度 / 最低信心門檻過濾。永不自動替換，
故最壞情況只是一個可按 Esc 消掉的小窗。

## 模組拆分（各自獨立、可單獨測試）

| 模組 | 職責 | 相依 |
|---|---|---|
| `src/engine/layout.js` | 大千對照表 + `鍵位字串 → 注音音節[]`（純函式） | 無 |
| `src/engine/dict.js` + 詞庫資料檔 | 注音→詞＋詞頻查詢 | 詞庫資料 |
| `src/engine/convert.js` | `convert(亂碼) → 漢字候選[]`，詞庫選字 | layout、dict |
| `src/engine/detect.js` | 三道關卡、信心分數 | layout、dict、英文字表 |
| `src/content/content.js` | 監看輸入框、追蹤游標、統籌偵測與替換 | engine、popup |
| `src/content/popup.js` | Shadow DOM 候選浮窗、鍵盤/點擊選字 | 無（純 UI） |
| `src/options/` | 設定頁：開關、保守／積極、啟用網站 | chrome.storage |
| `manifest.json` | MV3 設定，權限最小化（content_scripts、storage） | — |
| `build/build-dict.js` | 開發期：把來源詞庫壓成前端精簡格式（產物才進版庫） | — |

### 邊界界定

- 內容腳本碰得到**網頁內**的輸入框（input / textarea / contenteditable，含 FB 留言框）。
- 碰不到（也不需要）Chrome 網址列等瀏覽器本身 UI。

## UI

### 就地候選窗
- 以 **Shadow DOM** 渲染，隔離網站 CSS。
- 定位於游標旁（Selection/Range API 取座標；純文字框以鏡像技巧估算）。
- 內容：主候選（藍底，Enter 採用）＋2 備選（數字鍵 2/3 或點擊）＋「Esc 忽略」提示。

### 設定頁
- 啟用／停用開關。
- 偵測靈敏度：保守（預設）／積極。
- 之後可擴充：套用哪些網站、其他鍵盤佈局。

## 技術風險（皆可控）

1. **偵測誤判**：以三道關卡 + 保守門檻 + 永不自動替換化解；使用者洞察（英文不含聲調鍵、且組不成合法音節）已大幅降低誤判。
2. **FB 富文字（React/contenteditable）替換**：直接改 DOM 會與框架衝突，須以模擬輸入事件方式替換；MVP 先做穩純文字框與基本 contenteditable，FB 專門調校。
3. **游標螢幕座標**：contenteditable 用 Range API；純文字框用鏡像技巧。做不好僅影響浮窗位置，不影響功能。

## 資料與授權

- 詞庫需採用授權清楚、可散布的開源注音詞庫（如 libchewing 系）。實作前先查證授權，
  再以 `build-dict.js` 前處理成精簡格式（壓縮後約 1–3 MB，隨擴充打包）。

## 測試（TDD）

- `layout.js`：`JI394T AU04 → 我愛吃麵` 級的鍵位→注音、各聲調、無法對應字元。
- `convert.js`：已知詞組選字（愛吃 vs 礙尺）。
- `detect.js`：亂碼 vs 真英文分類（重精確率，避免誤擾）。
- golden 範例集當回歸測試。

## 散布

- 打包上架 Chrome 線上應用程式商店（開發者帳號一次性 US$5），一鍵安裝。
- 或免費：打包資料夾以「開發人員模式」載入。
- 純前端、離線可用，託管與散布皆單純。

## 明確不做（MVP 之外，列為未來增強）

- 點字換字以外的完整選字介面。
- 智慧偵測「句中哪一段才是亂碼」（MVP 針對連續亂碼段）。
- 大千以外的佈局。
- FB 以外網站的逐站深度調校。
