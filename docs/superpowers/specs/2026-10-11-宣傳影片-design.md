# 宣傳影片 — 設計

日期：2026-10-11　對應產品版本：v1.1.7（選取整段一次還原）

## 要做什麼

兩支 30 秒的直式短影音，給 Threads、Instagram Reels 用：

| 版本 | 情境 | 給誰看 |
| --- | --- | --- |
| 課堂版 | 聽教授講課時邊聽邊打筆記 | 學生 |
| 會議版 | 開週會時邊聽主管講邊打紀錄 | 上班族 |

兩支共用同一套動畫，只換投影片、筆記標題與筆記內容。

## 不做什麼

- **不實拍、不入鏡。** 全部用程式生成。參考對象（錢花園的介紹影片）從頭到尾沒有
  實拍，質感正來自這一點；一個人做，也少了相機、燈光、演員這些失敗點。
- **不配旁白。** 只用字卡與節奏。
- **不放背景音樂。** 上架時在 Instagram／Threads 內建的音樂庫挑 —— 那些有授權；
  自己嵌進影片的音樂反而有版權風險。影片只帶打字聲。
- **不出現第三方的商標。** 聊天視窗、文件視窗都用自己畫的通用樣式，不放 LINE、
  Word 的名稱或圖示。
- **不沿用錢花園的黑底金字。** 它的黑金配它的金幣 Logo；我們的產品介面是白底，
  Logo 是青綠與粉紅，硬套會互相打架，而且一看就是借來的。

## 腳本（兩版共用的節奏）

### 一、整節課／整場會（0–9 秒）

| 秒 | 畫面 |
| --- | --- |
| 0–1 | 上方三分之一是投影片，下方是空白的筆記文件，右上角一個小時鐘 `10:02` |
| 1–2 | 第一行用正常的中文打出筆記標題 |
| 2–8 | 之後打出來的全是英文亂碼，一行接一行。打字聲不停、**一次退格都沒有**。投影片每兩秒換一頁，時鐘快轉到 `10:48` |
| 8–9 | 投影片換成結束頁，打字聲停，畫面靜止一秒 |

觀眾會比打字的人更早發現 —— 真的在看螢幕的人第一行就會停下來。
這個「看著它發生卻無法阻止」的感覺，比拍一張臉更有力。

### 二、低頭（9–11 秒）

整頁筆記，只有第一行是中文。字卡：「**整節課的筆記。**」→ 停半秒 →「**全是亂碼。**」
（會議版：「**整場會的紀錄。**」）

### 三、救回來（11–18 秒）

| 秒 | 畫面 | 字卡 |
| --- | --- | --- |
| 11–12 | 整頁反白，浮出按鍵圖示 `Ctrl` `Alt` `Z` | — |
| 12–13 | 產品的浮窗：「→ 〔第一行〕　還原 5 行」 | — |
| 13–15 | 按下 Enter，亂碼由上往下逐行翻成中文 | 「**一整段，一次救回來**」 |
| 15–18 | `10/24` 與 `10:30` 兩行用底色標出，完全沒被動到 | 「**日期、時間，原樣保留**」 |

### 四、平常打字也接得住（18–25 秒）

| 秒 | 畫面 | 字卡 |
| --- | --- | --- |
| 18–19 | 切到通用的聊天視窗 | 「**下次，打錯當下就提醒你**」 |
| 19–21 | 打出 `ji3u3ru/ 2l4x.6vu84xk7`，候選窗浮出「我已經到樓下了」 | — |
| 21–23 | **畫面凍結兩秒**，輸入框裡的亂碼一個字元都沒變 | 「**不按 Enter，它不會動你的字**」 |
| 23–25 | 按下 Enter，換成中文送出 | — |

21–23 秒那兩秒不能剪。它證明的是產品最硬的一句承諾：永遠不會自動替換。

### 五、收尾（25–30 秒）

| 秒 | 畫面 |
| --- | --- |
| 25–27 | 四張大字卡快速切換：救得回 → 改得準 → 不亂動 → 到處用 |
| 27–30 | Logo 的 ㄐ、鉛筆、A 三個元素飛入組合 →「注音亂碼偵測」→「忘了切輸入法，不用重打。」→ `b96093.github.io/bopomofo-garble-detector` → 接回開頭 |

## 筆記內容（已驗證）

每一行亂碼都經過兩步驗證：(1) 從詞庫反推這句中文在注音鍵盤上會打出哪串英文；
(2) 把整段丟進產品實際使用的 `DetectBlock`（`desktop/engine.ahk`），轉回來與原句
**一字不差**才採用。2026-10-11 驗證時，三輪共試了 37 句不重複的候選，只有 12 句通過 —— 隨手寫的句子
大約一半會被轉成同音的別字（例如「鐘」→「中」、「客服」→「克服」、「寄」→「繼」），
所以**不可以自行替換句子**。要改內容，必須重跑驗證。

## 製作方式

```
video/scene.html     一頁 HTML，所有動畫都由 render(t) 依時間 t 畫出
video/content.js     兩個版本的內容（投影片、筆記、浮窗文字）
video/render.mjs     用無頭 Chrome 逐格截圖，再交給 ffmpeg 合成 MP4
```

- **逐格決定，不靠即時播放。** `render(t)` 只依 t 決定畫面，同一個 t 永遠畫出同一格。
  錄出來不會掉格、不會因為電腦忙而卡頓，改一處重錄結果完全可預期。
- **不安裝任何套件。** 用 Node 24 內建的 WebSocket 直接透過 Chrome DevTools Protocol
  控制本機已安裝的 Chrome，不需要 npm 下載 Puppeteer。
- 每支 900 格 PNG → ffmpeg 合成 H.264（yuv420p），平台相容性最好。
- 打字聲以 ffmpeg 合成短促的按鍵聲，時間點與畫面上的每個字對齊。

輸出：`dist/video/注音亂碼偵測-課堂版.mp4`、`dist/video/注音亂碼偵測-會議版.mp4`

## 怎麼驗收

1. 每支在關鍵時間點（1、5、9、10、12.5、14、16、20、22、24、26、29 秒）各截一張圖，
   逐張檢查：文字有沒有破字、浮窗跟產品真的長得一樣、亂碼與還原結果跟上面的表格
   一字不差。
2. 檢查無縫循環：第 30 秒的畫面要能接回第 0 秒。
3. 兩支成品交給使用者看過，再決定要不要調整節奏。
