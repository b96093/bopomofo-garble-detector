# 版本比較影片 — 設計

日期：2026-10-12　對應版本：桌面版 v1.1.8、Chrome 擴充 1.0.3

## 要做什麼

一支約 90 秒的**說明影片**，放在網站首頁（`docs/index.md`）「兩個版本」那一節。
看的人已經想裝了，進到首頁才發現有兩個版本 —— 影片要讓他在一分半內知道：
哪裡用哪一版、哪些地方 Chrome 版幫不上忙、最後為什麼建議兩個都裝。

這是說明，不是宣傳：不需要懸念、不需要 Logo 動畫，看完能做決定就好。

## 不做什麼

- **不實拍、不配旁白、不放背景音樂。** 同宣傳片。
- **不放第三方的圖示或配色。** 瀏覽器、信件、聊天軟體、文書軟體、Google 文件都畫成通用樣式。
  字卡與總結卡會**寫出** Facebook、LINE、Word、Google 文件的名稱 —— 這支影片的重點就是
  「哪個程式用哪一版」，屬於描述性用法，README 也是這樣寫。
- **不提沒驗證過的事。** 例如 Chrome 擴充在 Mac 上能不能用，沒有驗證過，不提。
- **不改網站。** 把影片嵌進首頁、首頁加「請用電腦開啟」的提示，另外處理。

## 版面

- **頂端：兩盞燈** ——「Chrome 版」「桌面版」，一直掛著。現在是哪一版在幫忙，那盞就亮。
  觀眾不用讀規則，看幾次燈亮就會記住「哪裡用哪版」。
- **中間：這一站的畫面**，左上角一個時鐘標示現在幾點（一天的行程）。
- **底部：字卡**，說明這一站的重點；每張至少停留到讀得完（約每秒 6 個字）。

## 產品介面必須跟真的一樣

- **Chrome 版候選窗與小按鈕**：直接 `import` 擴充本身的 `src/content/popup.js`（`createPopup`）與
  `src/content/hint.js`（`createHint`）畫出來 —— 它們是純 DOM 元件，不依賴 `chrome.*` API。
  候選與同音字來自擴充引擎的 `detect` 實際輸出。對照組：2026-10-12 使用者的 YouTube 截圖。
- **桌面版候選窗**：同宣傳片，用 `video/dump-popup.ahk` 從產品的 `BuildLayout` 匯出繪圖指令；
  聊天沿用 `video/popup.js`，Google 文件那句另外匯出一份。
- **桌面版整段還原的浮窗**：同宣傳片，照 `BuildIcon` 重建。
- 只在產品介面**外面**加柔和陰影，不套黑框與硬陰影。

## 製作方式

沿用宣傳片的整套做法（逐格決定、無頭 Chrome 截圖、Node 合成打字聲、ffmpeg 輸出）：

```
video/compare.html          這支影片的畫面，render(t) 依時間畫出每一格、state() 從 DOM 讀狀態
video/compare-content.js    這支影片的文字內容（上表）
video/render.mjs            擴充成可以指定要輸出哪支影片與尺寸
video/check-compare.mjs     核對各時間點的畫面狀態（燈、字卡、候選窗、總結卡）
video/verify-content.mjs    擴充成也驗證這支影片的內容（Chrome 句子用 JS 引擎、桌面版句子用 AHK 引擎）
```

- 從 `file://` 載入 ES module 會被 Chrome 擋下，`import` 擴充元件需要處理（例如讓 render 時用本機 HTTP 伺服器，
  或啟動參數）—— 在實作計畫裡決定，並以實際能載入為準。
- 宣傳片的檔案（`scene.html`、`content.js`、`check.mjs`）不動；它的 68 項檢查必須照樣通過。

## 怎麼驗收

1. `node video/verify-content.mjs`：宣傳片與這支影片的每一句都通過。
2. 畫面檢查：每一站的燈、時鐘、字卡、候選窗內容正確；總結卡的四列與設定提醒都在；
   同一個 t 永遠畫出同一格。
3. 每一站各截幾張靜態畫面逐張看：字有沒有破、產品介面跟真的一樣、手機尺寸下字讀得到。
4. 成品：1080×1080、30fps、約 90 秒、有音軌。交給使用者看過再決定要不要調整。
