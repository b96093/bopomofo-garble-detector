# 選取轉換支援整段 — 設計

日期：2026-09-28　目標版本：v1.1.7

## 要解決的問題

選取轉換目前只救得了一句話，救不了一段筆記。

實測（`desktop/engine.ahk` 的 `Detect`，選取轉換用的參數 `0.5 / 1 / manual`）：

```
單行（37 字元）      → 明天早上9點開會不要遲到        ✅
兩行（中間一個換行） → （轉不出來）                   ❌
121 字元的單行       → 引擎轉得完全正確，但被上限擋掉  ❌
```

兩個獨立的關卡：

1. **換行**。`IsRunChar` 不收 `\n`，而 `Detect` 逐字檢查，一碰到就整串 return ""。
2. **長度**。`CheckSelection` 有 `StrLen(text) > 120` 的硬上限，超過直接放棄。

## 為什麼現在要改

這個限制是**被動偵測時代**留下來的。當年每次拖曳、每次雙擊都會呼叫
`CheckSelection`，寬鬆門檻會讓版本號、IP、電話號碼統統跳出圖示，所以要卡死。

現在只有快捷鍵與系統列選單會呼叫它——使用者已經明確說「轉這一段」。同一個函式
裡幾行之外就有同樣理由的註解（門檻放寬到單音節、跳過常見英文那關）。120 這個
數字是最後一個沒跟上的遺留。

而真正暴露它的是一個具體場景：**聽報告時邊聽邊打筆記，眼睛在講者身上不在螢幕上，
一整段打完才發現全是亂碼。** 這是本工具最有價值的使用時機——你不會發現，因為
你根本沒在看——而它正好是目前救不了的那一種。

`docs/video-plan.md` 把事後補救列為「最被低估的功能」。它被低估的原因之一，
可能就是它救不了真正需要被救的量。

## 不做什麼

- **不動打字偵測路徑。** `Scan` / `DetectTail` / `BufferLanded` 完全不碰。
- **不動候選窗版面。** `draw.ahk` 的 `BuildLayout` 不改。
- **不改單行行為。** 單行的一切——三個候選、逐字換同音字、icon 位置——必須
  逐位元相同。這是回歸測試要證明的第一件事。

## 設計：一句與一段走不同的路

### 路由規則

```
選取內容含換行，或長度超過 SINGLE_MAX  →  整段路徑
否則                                    →  現況的單行路徑
```

`SINGLE_MAX` 是「候選窗還能好好顯示」的長度。它不是猜的——候選列的寬度由
`draw.ahk` 的 `LY.candH` 與 `Fit()` 決定，實作時量出候選窗在不換行的前提下
放得下幾個字，用那個數字，並在程式碼裡註明量測方式。

這條規則同時解掉一個原本沒被看見的問題：**一個三百字元、不含換行的長句，
走單行路徑一樣會把候選窗撐爆。** 現在它會被路由到整段路徑。

### 一句（單行且不超長）——現況，完全不動

精修工具。候選窗、三個整句候選、逐字換同音字。

### 一段（含換行或超長）——新路徑

```
選取 → Ctrl+Alt+Z → icon 顯示「→ 我已經到樓下了⋯　還原 8 行」
                  → Enter → 整段一次替換，不開候選窗
```

逐行獨立判斷：

- 是亂碼的行 → 換成第一候選
- **不是亂碼的行 → 原樣保留**（真實筆記必然中英混雜，忘記切之前打的那幾行是中文）
- 空行 → 保留

若某一行轉錯，使用者選那一行再按一次快捷鍵，就回到現有的單行候選窗流程去精修。

### 取捨：整段路徑跳過候選窗

代價是使用者按 Enter 前看不到完整結果，只看到「還原 8 行」，違背本工具
「你看得到才動手」的一貫原則。

仍然這樣做，理由有二：

1. 替換後 `Ctrl+Z` 可以復原，不是不可逆的操作。
2. 「整段都是亂碼」的當下，沒有什麼好挑的。十行裡選哪個同音字不是那個時刻的
   問題，**救回來**才是。挑字留給事後選單行精修。

替代方案是改候選窗版面讓它顯示整段預覽，但那要動 `draw.ahk` 的版面計算，
範圍大很多，且對這個場景沒有增加多少價值。

## 實作範圍

| 檔案 | 改什麼 |
| --- | --- |
| `desktop/engine.ahk` | 新增 `DetectBlock(text, dict)`：按 `\n` 切行，逐行 `Detect`，回傳各行結果與「有幾行是亂碼」 |
| `desktop/app.ahk` | `CheckSelection` 判斷單行／多行，分派到兩條路；放寬長度上限 |
| `desktop/app.ahk` | 新增整段替換的確認路徑（icon → Enter → 直接替換） |

`DetectBlock` 放在 `engine.ahk` 而不是 `app.ahk`，因為它是純函式、不碰全域狀態，
測試才能直接 `#Include` 它——與 `report.ahk` 拆出來的理由相同。

## 長度上限

不用猜。逐行轉換的成本隨行數線性成長，實測找出「開始有感延遲」的長度，用那個
數字訂上限，並在程式碼裡記下實測值與日期。

上限仍然要有：`GetSelectedText` 走剪貼簿，而 `Detect` 對每一行都要跑
`TokenizeResolving` 與 `ConvertCandidates`。

## 怎麼驗證

1. **先寫失敗的測試**（新檔 `desktop/test-block.ahk`，`#Include` 真的 `engine.ahk`）：
   - 兩行純亂碼 → 兩行都還原
   - 中英混雜（第一行中文、第二行亂碼）→ 中文原樣、亂碼還原
   - 空行保留
   - 121 字元單行 → 不再被擋，且被路由到整段路徑（不進候選窗）
   - **單行輸入走 `DetectBlock` 的結果，必須與直接 `Detect` 相同**
2. 改完讓它們過。
3. 既有 `test-uia.ahk`（13 個）與 `test-report.ahk`（16 個）不得退步。
4. `check-globals.py` 不得報錯。
5. 實機驗證：在 Word 裡貼一段多行亂碼、全選、按快捷鍵。

## 示範字串

影片與手動測試只能用下列已驗證字串（首選＝原句，2026-09-28 於靈敏度 4 複驗）：

| 亂碼 | 還原 |
| --- | --- |
| `ji35p 2k7cp3vu3cj0 su3` | 我真的很喜歡你（次選「妳」） |
| `ji3u3ru/ 2l4x.6vu84xk7` | 我已經到樓下了 |
| `au/6wu0 yl3g;392u03d9 cjo31j4ul t62l4` | 明天早上9點開會不要遲到 |

自行發明的字串約一半會失敗（實測：`我馬上下`→「我抹是下」、`沒事`→「兩使系」）。
要新增句子必須先用引擎跑過。
