# 更新提示與問題回報 — 設計

日期：2026-08-30　目標版本：v1.1.5

## 要解決的問題

**一、使用者不知道有新版。** 桌面版沒有任何版本檢查機制，裝好之後除非自己回
GitHub 看，否則永遠不會知道更新。2026-08-30 一天發了五個版本修掉七個 bug，
對現有使用者而言等於什麼都沒發生。

**二、回報門檻太高，而且收到的資訊沒用。** 設定頁已有「回報問題」按鈕，但它
只是開啟 GitHub Issues。使用者要描述問題得自己寫，而最關鍵的資訊——「在哪個
程式、畫面讀不讀得到」——他根本不知道要提供。今天解掉的每個問題，關鍵都是
這類對照。

## 不做什麼

**不做自動遙測。** `docs/support.md` 已公開承諾「這個工具刻意不做任何遙測」。
自動蒐集會摧毀這個專案最難被取代的信任資產。

**程式不主動連網。** 曾考慮「啟動時查詢 GitHub 版本號」，並討論過預設關閉的
選項。最後放棄，理由是任何 HTTP 請求都必然讓對方看到 IP 位址與連線時間——
即使不送任何內容，「完全離線」這句話也不能再講。改由使用者的瀏覽器去連線。

## 一、查看是否有新版

設定頁版本號旁邊加一顆按鈕，按下用 `Run()` 開啟瀏覽器到 Releases 頁面。

```
注音亂碼偵測  1.1.5    [查看是否有新版]  [回報問題]
```

程式本身零網路請求，隱私說明不需更動。

**已知限制**：使用者必須主動按，觸及率低。這是為了保住「零網路請求」而付出的
代價，是刻意的取捨。此功能也救不了目前已安裝的使用者——他們要先更新才會拿到，
而「不知道有更新」正是要解決的問題。現有使用者只能靠社群觸及。

## 二、回報問題視窗

「回報問題」改為先顯示一個視窗，把要提供的資訊攤開來讓使用者過目。

### 為什麼攤開而不是直接複製到剪貼簿

1. **與定位一致。** 標榜不蒐集資料的工具若說「我幫你把系統資訊複製好了」，
   即使內容無害也會引起不安。攤開來反而建立信任。
2. **剪貼簿是這個專案的敏感區。** `18d1acd` 修過「自動搶剪貼簿導致截圖被吃掉」。
   複製只在使用者按下按鈕時發生。

### 視窗內容

```
下面這些資訊有助於排查問題。不含你打過的任何內容。

  注音亂碼偵測 1.1.5
  Windows 11 (26200)  縮放 125%
  偵測靈敏度：4（積極）
  在 Chrome 中也偵測：開

  最近一次偵測
    程式：LINE.exe
    畫面讀取：讀不到
    判定：退回輸入法查詢

[複製]  [前往 GitHub 回報]  [關閉]
```

文字框唯讀但可選取，使用者可自行 `Ctrl+A` `Ctrl+C`。

### 「最近一次偵測」的時機問題

使用者是**開了設定頁之後**才按回報，那一刻的前景程式是設定視窗本身，不是出問題
的程式。最有價值的欄位在按下按鈕當下已經抓不到。

解法：`Scan()` 每次執行時記下三個值到記憶體——程式名稱、UIA 讀取結果、判定代號。
只記這三樣，不記緩衝內容、不記使用者打的任何字、不寫檔案，程式關閉即消失。

只保留最近一次，不做歷史列表。理由是可驗證性：使用者能逐行看懂並確認沒有自己的
內容；一份「最近 5 筆」的列表看起來就像日誌，即使內容一樣無害，觀感差很多。而
使用者遇到問題通常會立刻去開設定頁，最後一次現場通常就是問題現場。

## 影響範圍

| 檔案 | 改動 |
| --- | --- |

| `desktop/test-report.ahk` | 新增，測試報告文字產生 |

## 測試

報告文字的產生做成純函式 `BuildReport()`，接受狀態、回傳字串，可直接單元測試
（照 `test-uia.ahk` 的模式，直接測產品程式碼而非另抄鏡像）。視窗本身以手動驗證。

驗收條件：

- 按「查看是否有新版」會開啟瀏覽器到 Releases 頁，程式無網路請求
- 在 LINE 打字觸發偵測後開設定頁按「回報問題」，報告中的程式名稱為 `LINE.exe`
- 報告中不含任何使用者輸入的內容
- 「複製」只在按下時寫入剪貼簿
