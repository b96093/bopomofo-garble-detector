# 桌面版實作計畫（計畫 4）— Word / PPT 等所有 Windows 程式

> 使用者選擇：**全域鍵盤監聽自動偵測** + **獨立 exe**，工具鏈 **AutoHotkey v2**。
> 兩者皆為高風險選項（防毒），故**第 0 階段先做可行性驗證**，不通過就停下重談。

**Goal:** 常駐系統列的小程式，在任何 Windows 程式（Word、PPT、LINE…）打注音亂碼時自動跳候選窗，選字後就地替換。體驗比照 Chrome 版。

**共用詞庫：** `desktop/dict.txt`（由 `src/engine/dict-data.js` 產生，與 Chrome 版同源，維護一份）。

---

## 設計原則（因為是全域鍵盤監聽）

- 只在**記憶體**保留當前這一小段輸入，偵測完即丟；**永不寫入任何檔案**。
- **完全不連網**。
- 系統列圖示明顯可見，一鍵暫停／結束；提供暫停熱鍵。
- 遇到 Enter／Tab／Esc／方向鍵／滑鼠點擊／切換視窗 → **立即清空緩衝**。

---

## 階段 0：可行性驗證（最優先，失敗就停）

不寫完整功能，先用最小腳本確認三件事：

1. **防毒是否放行** —— 全域監聽腳本能否執行、Ahk2Exe 產出的 exe 能否執行不被封鎖。
2. **替換是否可行** —— 在記事本與 Word 裡送退格 + 貼上中文，位置是否正確。
3. **詞庫載入速度** —— 133,467 行載入 AHK Map 需要多久（可接受上限：啟動 5 秒內）。

→ **驗證方式**：實際執行，請使用者回報結果。任一項不通過就回頭重新討論方案。

## 階段 1：引擎移植（可自動驗證）

把 Chrome 版引擎（`layout.js` / `convert.js` / `detect.js`）移植為 AHK：
token 化（含聲調鍵、落單數字／空白、標點）、貪婪斷詞、多候選、三道關卡、數字修正。

→ **驗證**：寫 `desktop/test.ahk`，跑與 Chrome 版**相同的黃金測資**並印出結果：

| 輸入 | 應得 |
| --- | --- |
| `ji394t au04` | 我愛吃面（候選含 我愛吃麵） |
| `su35 2l4a8 ?ji394su3` | 你知道嗎?我愛你 |
| `a93` + N + `ek7`（N=0–9） | 買N個 |
| `cj8 d9 ` | 花開 |
| `the cat sat` / `hello` | 不觸發 |

## 階段 2：監看與替換

- `InputHook` 觀察輸入（不攔截，字照樣送到原程式），累積緩衝、去抖動約 150ms。
- 偵測命中 → 取游標螢幕座標（`GetGUIThreadInfo`，取不到則退回滑鼠位置）。
- 選定後替換：送 N 次退格 → 用剪貼簿貼上中文（CJK 最可靠）→ **還原原本剪貼簿內容**。
- → **驗證**：記事本 → Word → PPT 實測。

## 階段 3：候選窗 UI

比照 Chrome 版的三區鍵盤導航：句子區 `↑↓`、逐字區 `←→`、同音字區 `←→↑↓`，
`Enter` 確定、`Esc` 退回；浮窗不奪取焦點（否則會打斷 Word 的輸入）。

## 階段 4：系統列 + 設定 + 編譯

托盤選單（暫停／繼續、靈敏度保守／積極、開機自動啟動、結束）；
Ahk2Exe 編譯成單一 exe；撰寫安裝說明。

---

## 已知限制（誠實列出）

- **密碼**：全域監聽無法可靠辨識密碼欄位，你打的密碼會短暫進入記憶體緩衝（不寫檔、不外傳）。
  建議打密碼前用熱鍵暫停；程式會在按下 Enter／Tab 時立刻清空緩衝。
- **游標定位**：部分程式（尤其自繪介面）取不到游標座標，浮窗會改跳在滑鼠附近。
- **替換方式**：靠「退格 + 貼上」，在少數自訂編輯器可能不精準。
- **遊戲／全螢幕程式**：多半無效。
- **防毒**：可能仍被誤判，需加白名單（階段 0 先確認）。
