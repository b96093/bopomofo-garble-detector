# 競品分析與可行方向

日期：2026-09-09

本文分成三個信心層級。**「已驗證」是我實際執行過並看到結果的**，其餘標明來源與不確定性。

---

## 一、已驗證（實際執行過）

### 1. 引擎可以獨立跑在網頁上

```
grep -ln "chrome\." src/engine/*.js  →  無任何檔案命中
```

`src/engine/` 六個模組**完全沒有使用 chrome API**。要做線上版不需要重寫引擎，直接搬。

### 2. 詞庫大小

| | 大小 |
| --- | --- |
| 原始 `dict-data.js` | 5.28 MB |
| gzip -9 | **1.45 MB** |
| brotli -q11 | 1.15 MB |

GitHub Pages 會自動 gzip。1.45 MB 對單頁工具可接受，且可延遲載入（使用者真的輸入才載）。

### 3. 競品 ToolsKK 實測

在 `toolskk.com/zhuyin-decode` 實際輸入十組字串，記錄輸出：

| 情境 | 輸入 | 我們的引擎（打字偵測） | ToolsKK |
| --- | --- | --- | --- |
| 基本句 | `ji394t au04` | 我愛吃**面** | 我愛吃**麵** ✅ 他們較好 |
| 長句 | `su3gji su394xk71j4e9 942k7bp6` | 你說你愛了不該愛的人 | 你說你愛了不該愛的人（平手） |
| 告白 | `ji35p 2k7cp3vu3cj0 su3` | 我真的很喜歡你 | 我真的很喜歡你（平手） |
| **數字與標點** | `au/6wu0 yl3g;392u03d9 cjo31j4ul t62l4` | **明天早上9點開會不要遲到** ✅ | 明天早賞 |
| 沒有空格 | `su3gji su394xk71j4e9942k7bp6` | 你說你愛了不ㄍ9愛的人 | 你說你愛了不（兩邊都不對） |
| 單一個詞 | `su3gji` | **你說** ✅ | 你 |
| 大寫 | `JI394T AU04` | **我愛吃面** ✅ | 我愛 我愛 |
| **真英文** | `hello world` | **不轉換** ✅ | **hello=world**（把英文弄壞了） |
| 電話號碼 | `0912345678` | 不轉換 ✅ | 0912345678（平手） |
| 混入真英文 | `ji394t au04 ok` | 不轉換 ✅ | 我愛吃麵 我愛吃麵 |

**結論**：ToolsKK 在「乾淨、有空格、常見句子」的表現與我們相當甚至更好。
但只要出現**數字、標點、大寫、沒空格、夾雜真英文**，它就明顯崩壞 ——
最嚴重的是它會把純英文 `hello world` 改成 `hello=world`。

### 4. 我們自己的弱點（同樣是實測）

| 問題 | 實際輸出 |
| --- | --- |
| 首選用字 | `ji394t au04` → 我愛吃**面**（ToolsKK 給「麵」） |
| **版本號誤判** | `v1.1.5` → **ㄒ1區1洲**（打字偵測就會誤觸發） |
| 選取轉換過於寬鬆 | `0912345678` → 091234直7啊；`192.168.0.1` → 192區168區0區1 |

版本號那個是**打字路徑就會發生**的誤判，優先度較高。
選取轉換的兩個是刻意放寬門檻的後果（使用者已明確指定要轉），但輸出品質很差。

### 6. 華碩智慧輸入法實測（2026-09-09，實機安裝後執行）

**方法**：安裝華碩智慧輸入法、切到混合模式，用模擬按鍵送出與我們相同的字串，
再把結果複製出來比對。**輸出字串是從剪貼簿讀出的精確值，不是螢幕辨識。**

> 方法上的前置發現：模擬「輸入文字」是直接注入 Unicode，**不會經過輸入法**；
> 送「按鍵」才是真正的虛擬鍵碼，輸入法會處理。這決定了測試可不可行。

| 測試 | 華碩混合模式 | 我們 | ToolsKK |
| --- | --- | --- | --- |
| `ji394t au04` | **我愛吃麵** ✅ | 我愛吃**面** | 我愛吃麵 |
| `hello world` | **hello world** ✅ 另提供注音選項 | 不轉換 ✅ | hello=world ✗ |
| `su3gji su394xk71j4e9 942k7bp6` | 你說你愛了不該愛的人 ✅ | 相同 ✅ | 相同 ✅ |
| `au/6wu0 yl3g;392u03d9 cjo31j4ul t62l4` | 明天早**賞**9點開**毀**不要遲到 ✗ | **明天早上9點開會不要遲到** ✅ | 明天早賞 ✗ |

**結論一：華碩的混合模式是真的有效。** 不必切換、不必選字，直接輸出正確中文，
而且 `hello world` 沒有被誤判。這不是行銷話術。

**結論二：但它會把錯字直接寫進文件。** 含數字標點那句它錯了兩個字，且沒有徵詢
使用者。我們在同一句全對；即使錯了也只是跳出候選窗，按 Esc 即可。

**這是結構差異**：華碩幫使用者決定，我們問使用者要不要。

**未能驗證的項目**：框選查詢（連按兩次 Ctrl）在記事本中無任何反應，但這不足以
證明華碩做不到 —— 可能是按鍵間隔未被判定為連按。較可靠的依據是華碩官方文件：
八項功能中框選查詢寫的是「顯示**翻譯**結果」，且無任何一項轉換已存在的文字。

**附帶觀察**：同一次測試中，以 Unicode 注入寫入的字面亂碼（模擬「別人傳給你的字」），
**我們的工具正確偵測並跳出候選窗** —— 那是輸入法結構上做不到的事。

## 二、查到但未親自驗證（來自搜尋，二手資訊）

### 華碩智慧輸入法

- 是**完整的輸入法**，取代原本的注音，核心是中英混合模式免按 Shift
- **並非所有華碩機型預裝**——華碩官方 FAQ 明寫「若為非預裝應用程式的機種型號，需要參考連結獲取並安裝」
- 從 Microsoft Store 下載，因此**沒有 SmartScreen 警告，且自動更新**
- 已被 T客邦、YouTube、巴哈姆特等媒體報導過
- 使用者回報的問題（部落格與論壇個案，非系統性數據）：
  容錯率小、打太快的誤按會完整呈現、用兩個月後混合模式頻繁把英文誤判成中文、
  長文字時字元自動重複、用滑鼠移動游標而未先按 Enter 會整段消失、Photoshop 按鍵衝突

### Microsoft Store 上架（桌面版）

- AutoHotkey 有社群維護的 MSIX Store Edition，技術路徑存在
- **MSIX 會停用 UIAccess** → 在以系統管理員身分執行的程式裡，鍵盤 hook 收不到按鍵
- MSIX 檔案裝在唯讀的 `WindowsApps`，現行「settings.ini 寫在 exe 旁邊」與「捷徑做開機啟動」都需要改寫
- 開發者帳號一次性約 19 美元（相較程式碼簽章憑證每年 200～400 美元）

### Edge 擴充

- Edge 透過 Microsoft Partner Center 接受 MV3 擴充
- 我們的 manifest 已是 MV3、只用 `storage` 權限、無 webRequest、無遠端程式碼
- 依此判斷移植成本接近零，但**我沒有實際提交過，不確定審核細節**

## 三、我不知道的事

- **搜尋量**：那些線上解碼器每天有多少人用。我無法取得關鍵字工具數據。
- **商店審核**：Microsoft Store 對「全域鍵盤 hook」類工具的政策與通過機率。
- **華碩的實際誤判率**：只有零星論壇回報，沒有人做過系統性測試。
- **媒體是否願意報導**。

## 四、可行方向（依「成本 ÷ 確定性」排序）

### A. 修掉版本號誤判　成本：低　確定性：高

`v1.1.5` → `ㄒ1區1洲` 是實測到的誤判，打字路徑就會發生。開發者、工程師打版本號的頻率不低。

### B. Edge 擴充上架　成本：低　確定性：中

manifest 已符合，移植成本接近零。Edge 是 Windows 預設瀏覽器，在台灣有一定佔比。
未驗證：提交流程與審核時間。

### C. 線上版落地頁　成本：中　確定性：中

引擎可直接搬（已驗證），詞庫 1.45 MB 可接受（已驗證）。

**價值不只是 SEO，而是有實測支撐的差異化**：競品在數字、標點、大寫、
夾雜英文的情境下明顯崩壞，我們不會。落地頁可以直接把這幾組對照放上去。

未驗證：是否真的搜得到、有多少流量。

### D. 桌面版上架 Microsoft Store　成本：高　確定性：低

能一次解決 SmartScreen 與自動更新，並與華碩站上同一通路。
但需要工程改寫（設定檔、開機啟動）、失去 UIAccess、且審核結果未知。

**建議在 A/B/C 驗證出需求規模之後再評估。**

## 五、定位結論

不要以「打贏華碩」為目標。華碩的解法對「願意換輸入法的人」更根本，且有品牌與通路優勢。

**真正的對手是「什麼都不做」**——絕大多數注音使用者不知道任何解法存在，打錯了就刪掉重打。
線上解碼器每天有人搜尋，證明這個需求真實存在且未被滿足。

本工具的位置：**不動使用者的輸入法、能救已經存在的文字、在使用當下自己出現。**
這三點華碩與線上工具都做不到。
